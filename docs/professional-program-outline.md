# Professional AI Engineer Program

**AI Engineer: Zero to Professional.** A complete self-paced curriculum for people with no previous programming, computer science or AI experience.

Beginner friendly · 15 modules · Project based · Self-paced · 600 hours

The program starts with basic computer skills and programming, moves through mathematics, Python, data, machine learning and deep learning, then covers LLM applications, RAG and AI agents, and finishes with production deployment and a portfolio capstone.

The learner does not need:

- A university degree.
- Previous programming experience.
- Mathematics beyond basic school-level arithmetic.
- Previous AI or machine-learning knowledge.
- Paid software or API subscriptions. Every exercise has a free path (see [section 7](#7-learning-platform-and-technical-requirements)).

### Graduate profile

After successful completion, a learner can:

1. Write and test Python programs independently.
2. Use SQL to store and query data.
3. Understand the essential mathematics, statistics and AI concepts behind modern systems.
4. Prepare and analyze datasets.
5. Train and evaluate basic machine-learning models.
6. Explain neural networks and train simple deep-learning models.
7. Build applications on hosted and local LLMs.
8. Build RAG applications over private knowledge sources.
9. Build AI agents that use tools and multi-step workflows.
10. Evaluate, secure and monitor AI applications.
11. Deploy production-ready AI systems.
12. Document, demonstrate and maintain AI projects.

**Scope:** This is an applied AI engineering program. It teaches learners to engineer systems on top of existing models, alongside the foundations of ML and deep learning. It does not prepare someone to be an AI researcher or a foundation-model training specialist.

## Module 02: Computational Thinking

Beginner · **15 hours**

**Prerequisites:** Module 01.

**Purpose:** Teach learners to think like programmers (break problems down, describe steps precisely, predict what a program will do) before they learn Python syntax. **Learning outcomes.** Students will be able to:

- Explain what a program and an algorithm are.
- Break a problem into smaller steps.
- Write pseudocode and draw flowcharts.
- Describe variables, decisions, repetition and reusable steps in plain language.
- Trace a short program by hand and predict its output.
- Approach bugs methodically.

## 4. Assessment and grading framework

AI engineering is a practical discipline, so the course does not rely mainly on multiple-choice quizzes. Learners must show they can build working systems.

### Assessment structure

| Assessment type | Weight |
| --- | --- |
| Module quizzes and knowledge checks | 10% |

| Module assignments | 20% |
| Level projects (Levels 1–3, see section 5) | 20% |
| Final capstone project (Level 4) | 30% |
| **Total** | **100%** |

### Who grades what

A self-paced course needs a grading model that scales. Each assessment type is graded in the cheapest way that still checks real competence:

| Assessment | How it is graded |
| --- | --- |
| Quizzes and knowledge checks | Automatically, by the learning platform. |
| Coding laboratories | Automatically, with hidden pytest tests or notebook auto-grading. |
| Module assignments | Peer review against a published rubric, with staff spot checks. |
| Level projects | Staff review against a rubric, plus a short recorded walkthrough by the learner. |
| Capstone | Staff review, plus a live or recorded defense in which the learner explains and modifies their code. |

Staff time is the main running cost of the program. Budget for it per learner before launch.

### Project rubric

Module assignments, mini projects and level projects all use one rubric. Each criterion is scored at four levels: **Novice**, **Developing**, **Production-ready** and **Exemplary**. Each level is described in writing for every project, so peer reviewers and staff grade the same way.

| Criterion | Weight |

| Correctness and evaluation: it works, and the learner measured how well | 35% |
| Software engineering and reliability: tests, error handling, structure | 30% |
| System design and trade-offs | 20% |
| Documentation and security | 15% |

The capstone uses its own weights (Module 15). Every portfolio project, from Module 07 onward, includes at least one Architecture Decision Record (ADR) from the course template: the decision, the options considered and why one was chosen.

## 12. Design principles

1. **Don't skip programming fundamentals.** A learner who cannot write and test basic Python independently will struggle in almost every later module.
2. **Teach concepts before frameworks.** Build things from scratch first (an agent loop, a retrieval pipeline), then teach one framework as a practical implementation.
3. **Every level produces working software.** Learners must be able to demonstrate what they built, not only pass quizzes.
4. **Never require payment to pass.** Every exercise has a free path.
5. **Keep the core focused.** Advanced computer vision, speech AI, robotics, distributed training, CUDA and foundation-model research belong in separate advanced courses.
